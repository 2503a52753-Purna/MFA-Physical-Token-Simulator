Overview

The Big Picture: Why Hardware MFA?

❌ The Problem: Weak Passwords & SMS

  • Passwords are stolen: Over 80% of data breaches involve stolen static credentials.
  • SMS OTPs are easily intercepted: SIM-swapping and cellular network spoofing bypass SMS.
  • Phishing attacks: Fake websites easily capture static passwords and relay OTPs.

✅ Our Solution: Physical Hardware Token

  • Master Key Stays Offline: Stored in ESP32 microcontroller — never transmitted over the internet.
  • 30-Second Dynamic Codes: Computes cryptographically synchronized single-use codes.
  • AWS Zero-Trust Cloud: AWS Lambda verifies the token and blocks replay attacks instantly.
Architecture Flow

How It Works in 3 Simple Steps

1

Press Hardware Button

User pushes the button on the physical ESP32 token. The display calculates a fresh 6-digit OTP code valid for 30s.

2

Enter into Login

User types the 6-digit code into the Enterprise Cloud Login Portal (or clicks the 1-Click Auto-Fill helper).

3

AWS Cloud Verifies

AWS Lambda computes HMAC-SHA1 hash, accounts for clock drift (±30s), saves the step in DynamoDB, and unlocks access in 38ms!

Hardware Layer

ESP32 Hardware Token & OLED Screen

📟 Hardware Specifications

  • ESP32 DevKit-C v4: Dual-core 240MHz Xtensa processor.
  • 0.96" SSD1306 OLED: 128x64 pixels monochrome I2C display.
  • Tactile Push Button: GPIO 4 (Active-LOW interrupt).
  • Status LEDs: Power, Wi-Fi, MQTT Transmit, and AWS Auth.
  • Wokwi Simulator: 100% zero-hardware browser simulation!

Cloud Layer

AWS Cloud Backend Architecture

1. AWS IoT Core

MQTT Broker (TLS 1.2)

Ingests hardware telemetry on topic mfa/devices/+/otp and publishes ACK messages back to the token display.

2. AWS Lambda

Serverless Compute

Node.js 20.x compute handler computes HMAC-SHA1 RFC 6238 hash, checks ±30s drift tolerance, and executes in ~38ms.

3. Amazon DynamoDB

Zero-Trust Store

Stores token configuration and monotonically updates last consumed time steps to defeat replay attacks permanently.

Zero-Trust Security

Stopping Hacker Replay Attacks

🚨 The Threat: Replay Attack

A hacker eavesdropping on the network intercepts a valid 6-digit OTP code before its 30-second window expires. The hacker immediately re-submits the exact same code to gain unauthorized access!

🛡️ The Solution: Monotonic Step Tracking

When AWS Lambda validates an OTP, it immediately locks that step timestamp into DynamoDB. If anyone tries to reuse it:

HTTP 403: REPLAY_ATTACK_DETECTED!
